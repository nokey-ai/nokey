# Files

- [Command execution and output redaction](exec-and-redaction.md) - How nokey builds a child process environment from stored secrets (only/except filtering, reserved variable names), runs the child with signal forwarding, and redacts secret values and their encodings from its output, both streaming (CLI) and buffered (MCP).
- [macOS dedicated keychain and Touch ID](macos-keychain.md) - macOS-only storage features. Covers the opt-in dedicated keychain file, Touch ID unlock through byteness/keyring, partition-list "build trust" that stops per-upgrade password prompts, lock settings, and the keychain migrate, to-dedicated, from-dedicated, backup, restore and prune-orphan commands with sealed backups.
- [MCP server](mcp-server.md) - The nokey MCP server started by `nokey mcp serve`. Covers its seven tools, how a Handler is wired with injected dependencies, the per-call order of policy check, token/approval gateway, secret read, redacted run and audit, ${{NOKEY:NAME}} placeholders, exec options, timeouts and process-tree killing.
- [Architecture overview](overview.md) - How nokey is put together. Covers the single Cobra `cmd` package over `internal/*` libraries, config loading and the App context, and the end-to-end path from a stored secret to a redacted child process on the CLI (`nokey exec`), MCP (`nokey mcp serve`) and proxy routes.
- [Secret-injecting proxy](proxy.md) - The local HTTP/HTTPS forward proxy behind `nokey proxy start` and `nokey exec --isolate`. It decrypts HTTPS for hosts named in proxy rules (MITM), injects secret-bearing headers, enforces credential, SNI and Host checks, can block egress, and signs with a name-constrained local CA whose private key is stored in the keyring.
- [Secret storage and keyring backends](secret-storage.md) - How nokey stores secrets through its keyring.Store wrapper over byteness/keyring. Covers backend selection per OS and via --backend/NOKEY_BACKEND, secret-name validation and the reserved __nokey_ namespace for nokey's own state, caching, the verified rename, and migration of the encrypted file backend's directory.
