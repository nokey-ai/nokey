# Files

- [Approvals and session tokens](approval-and-tokens.md) - How the MCP server gets a human's consent. An elicitation prompt goes to the MCP client, followed by the OS presence dialog the agent can't answer. Covers prompt construction that resists forged lines, "don't ask again" grants, and the in-memory token (lease) store with minting limits, scope matching, use counting and revocation.
- [Audit log](audit-log.md) - nokey's optional audit log. Covers what an entry records (secret names, never values), the encrypted HMAC-chained append-only file with a chain-head checkpoint for detecting truncation and tampering, key storage in the keyring, in-process and cross-process locking, lazy compaction and retention, legacy migration, and which components record events.
- [Human presence, PIN and sessions](human-presence-and-pin.md) - The CLI's human-only gates. Covers the OS presence dialog (macOS Touch ID or login password), the confirmHuman fallback to a fresh PIN, PIN authentication (Argon2id, TTY-only, exponential backoff stored in the keyring), and sudo-style PIN session tickets bound to the PIN hash and the file's mtime.
- [Policy file](policies.md) - The semantics of policies.yaml. Covers rules mapping command patterns to secret patterns, approval modes and token_required, how commands are identified (bare name versus absolute path), how a missing policy differs from a policy with rules, digest-based approval through `nokey policy approve`, and hot reload in the MCP server.
- [Threat model](threat-model.md) - What nokey defends and what it doesn't. Covers the actors (the person at the machine, an AI agent or other program running as the same user, the child process), the trust boundaries the code enforces (keyring-held state over writable files, human-only confirmation, approved policy digests, redaction and the proxy), the documented gaps, and the security reporting policy.
